# Node.js 26 主机迁移

## 目标与当前状态

目标是以 Node.js 26 / TypeScript 全面替换仓库内 Python（包括主机、
构建、烧录、诊断和文档工具），集成完整 Moonraker 功能，并将宏转换为
消费级产品的受控操作。数学库按精度和目标板性能选择；必要时采用 Rust。
保留 MCU C 固件及现有 C 运动内核不构成 Python 残留。

初始基线：`ce7002be`，218 个 Git 跟踪的 Python 文件：`klippy` 179、
`scripts` 32、`lib` 6、`docs` 1。当前生产入口仍是 Python；`host/`
是迁移中的实现，尚不可用于控制打印机。不得将新增 TS 文件等同于原模块已替换。

开发从最新 `develop` 建立独立任务工作树，任务 PR → `develop` → `master`。
本机检查通过后还需集成与目标硬件验证；生产部署须在授权范围内执行。

## 宏的产品设计方向

面向用户提供打印准备、开始、暂停、恢复、取消、换料、校准等具名操作，
使用有版本的类型化参数与设备能力约束；用户不必编写模板或 G-code。
每个操作具有显式状态机、前置条件、进度、取消边界、超时、幂等标识、
资源互斥和可恢复记录。参数验证完成后才允许产生设备副作用。

温度上限、归零/位置有效性、运动范围、挤出温度等保护必须由主机核心执行，
不能依赖宏正确编写。断连/断电后的运动恢复须重新验证位置和设备状态，
不能盲目重放命令。旧宏导入必须生成可检查的操作或给出不支持原因；不得
通过 JS eval 或无限制脚本保留原有风险。兼容与专家入口需明确能力边界。
完整契约尚未全部实现。当前 `host/src/operations/print.ts` 提供版本化开始请求、
温度和文件标识校验、幂等开始、暂停/恢复状态约束、取消及失败停机。
取消会立即请求设备停止，并等待活动操作结束和安全停机确认后才报告取消完成。
设备适配器必须兑现 AbortSignal，拒绝取消后的迟到副作用，并在控制边界
重新验证安全条件。当前只有模拟适配器测试，没有连接打印机。
持久化幂等记录、重启恢复、文件注册、设备能力检查、操作/停机超时、
完成事件及下一任务生命周期仍未接入，不能作为生产级宏替代品交付。

## 精度与性能门禁

- 使用 binary64；MCU 的 64 位计数通过 BigInt/原生整数传输，禁止隐式降精度。
- 以原算法、独立解析解、几何/方程残差三种证据验证数学模块。
  奇异、近奇异、边界、不可达、NaN/Infinity、超大/超小量级须单独测试。
- 普通模块记录耗时与内存；热路径记录吞吐、p50/p95/p99、分配、GC、
  事件循环延迟和原生调用开销。校准与频谱计算必须离开运动调度线程。
- 同一机器、输入、预热、重复次数比较原 Python 与候选版本；本机微基准
  不代表目标板吞吐或打印速度。最终须在支持的目标板跑真实 G-code 回放、
  步进时间戳差分、满负载 API/文件传输及长时间运行，验证无队列饥饿。
- 未建立目标机型号、固件配置、允许步进时间误差、最大打印负载的实测基线
  前，禁止宣称运动精度和打印速度完整通过。
- 所有替代完成后移除 Python 入口、运行/构建依赖和临时 Python 对照执行器；
  保存版本固定的对照数据。逐文件审计及无 Python 环境构建/运行均须通过。

### 频谱校准与操作层（2026-09-19）

失败清理；终止 Worker 后才释放任务槽。它不是完整 shaper 搜索器。

开发对照需要可导入 NumPy 的 Python，仍仅用于开发，不属于主机运行依赖：

### 连接初始化与 RPC 调度基础（2026-09-20）

`downloadIdentify` 以 40 字节块下载固件字典，具有总期限（默认 5 秒）、
压缩数据容量（默认 1 MiB）、连续无进展响应次数（默认 8 次）上限。
错位响应重试当前偏移，错误类型、超长分片、空字典及错误压缩流均拒绝。
完成解压和字典验证后才返回新对象，调用者负责原子切换连接状态。
取消及超时向查询适配器传递 AbortSignal，并终止调用者等待；适配器必须
兑现信号并停止底层重传/写入。尚无串口/CAN 适配器，测试使用真实编解码

调用者必须提供授权钩子；用户、令牌、ACL 和网络监听仍待实现。

不向客户端暴露详情，远程 agent 的 null 结果可正确交付。
这些与上游的边界差异必须纳入后续完整客户端兼容评估。

### 主 MCU 时钟估计核心（2026-09-20）

`host/src/timing/clock-sync.ts` 移植时钟/发送时间的衰减回归、预测方差、
异常样本过滤、最低 RTT 老化、发送队列释放估计及系统时间双向换算。
+32 位响应计数向前扩展与查询历史时钟的最近值扩展分别实现，不能混用。
发送时间不明的重传响应只更新计数，不加入回归。倒序发送时间、倒置 RTT
及非法输入被拒绝。初始化和每次查询的实际调度仍由后续连接层负责。

计数保持 BigInt；浮点回归使用相对基准的偏移，超过 `2^40` ticks 重设局部
基准，避免把巨大运行时钟直接转成 Number。超出精确整数偏移范围的换算
会拒绝。单元测试以大于 `2^63` 的起点验证平移不变性，并以 20,000 次
更新覆盖基准重设。此改进仍须在目标板与真实时钟漂移下验收。

`npm run bench:clock` 用原 Python ClockSync 类对照 5,000 个回绕、延迟异常
和未知发送时间样本，4,617 次接受决定一致；频率差与预测 tick 差均为 0，
释放时钟和采样时间亦一致。相同桌面 CPU、Node 26.9.0 / Python 3.12.13，
3 次预热、11 次测量，TS 中位 0.782 ms / p95 1.495 ms，Python 中位
6.412 ms / p95 6.458 ms。本机更新性能门禁通过，不代表实时发送期限通过。

多 MCU SecondarySync、打印时间校准、周期查询、真实串口释放估计接入和
失联停机流程尚未迁移；原 Python clocksync.py 仍在活动路径中。
本批最终类型检查及 47 项测试通过；硬件与远程门禁仍未执行。

### G-code 串行调度基础（2026-09-20）

`host/src/gcode/dispatch.ts` 提供注册、就绪准入、扩展参数处理、原始文本
回退、一次性 ack、错误应答及异步处理器串行执行。脚本遇到命令错误立即
中止；有应答的交互输入在普通命令错误后继续。未知内部异常调用停机钩子，
协议输出不包含内部错误细节。处理器以 GCodeError 声明可报告的命令错误。

单个脚本最多 1 Mi 个 UTF-16 代码单元和 16,384 行，排队最多 64 个脚本。
同步处理约每 128 条让出事件循环，避免大文件持续占用调度线程。
紧急停止接口绕过脚本队列，发出 AbortSignal 并作废停机前排队的脚本；
即使恢复 ready，旧脚本也不能重新执行。异步处理器必须自行响应取消，
本层不会强制终止任意 Promise 或撤回已发送的 MCU 指令。硬件停止由钩子
实现；输入端必须识别紧急命令并直接调用 emergencyStop，不能将其排在
阻塞脚本后。当前无串口输入端，不能宣称 M112 全链路实时停机已通过。

`npm run bench:gcode-dispatch` 对照原 Python 调度器，10,000 条 G1 的
四轴/速度参数读取结果及应答逐值一致。3 次预热、11 次测量，同一桌面
Node 26.9.0 / Python 3.12.13：TS 中位 17.981 ms / p95 24.827 ms，
Python 中位 38.305 ms / p95 39.570 ms，中位约快 2.13 倍。该轮事件循环
延迟 p99 2.138 ms / 最大 5.329 ms；这是本机模拟处理器数据，非打印期限保证。

类型检查及全部 70 项测试通过，包含异步串行、停机、恢复后旧脚本拒绝与
长脚本让出测试。尚缺 mux 注册、状态/帮助接口、嵌套脚本执行、全部默认
命令语义和打印运行时接线；处理器不得等待同一调度器 execute 的排队任务，
否则会形成自等待。原 Python 调度入口仍然有效。
