## 目标与范围

最终目标：交付当前系列可安装、可打印、可维护、可升级及回滚的
Klipper＋完整原生 Moonraker 产品。Node.js 26／TypeScript 全面替代
Python，专用数学库及必要时 Rust 用于已证实的精度或性能缺口；现有
C MCU 固件及 C 运动内核可保留。构建、安装、启动、打印、维护、恢复
和日常测试全部无 Python，旧宏全部场景须转换为消费级受控操作。

当前只适配 **ANYRAID Cycnumbris 500 系列**；其他机型最后执行 G6。
已有 Delta 等回归只保护兼容行为，不构成新增机型适配。默认打印入口
仍为 Python，177 个跟踪 Python 文件均在 klippy；完整目标尚未完成。
不通过更换数学库、放宽容差或改变完成定义掩盖异常。

## 目标审视与执行调整

总目标保留，近期调度改为交付出口：**A 同包软件闭环 → B 当前系列
受控试验 → C 全面退役发布**。A、B 不等于完整替代；C 仍需全部
Moonraker 契约、旧功能／宏场景、目标性能与精度及 G1–G5 闭合。
试验必需能力、装配及 G3 通过后可进入 B，无须等待非试验必需的可选
Moonraker 集成；这些集成仍是 C 的必需条件。

总到分路径固定为：最终产品 → 阶段出口 → 用户操作 → 权威所有者 →
最小差额 → 必要验收 → 正常集成／切换。Python 台账用于最终退役核对，
不作为逐文件翻译队列；模块、提交、测试数量不表示整体完成率。
服务、身份／文件／历史、打印状态机、设备代际及恢复设施继续复用。

当前可确认的收口阻碍是同包完整客户端出口不足、#20 两处历史混合失败
未定位和 G3 未关闭。实际页面选择上传现已有证据，不再把工具
失效列为当前阻塞；继续候选审阅、正常集成及客户端验收。不能将这些因素推断为全部耗时的根因，
也不能用重新命名阶段、重复成功测试或迁移外围模块绕开出口。

### 近期交付承诺与调度边界

近期唯一主交付物为 **进入 develop 并完成同包实际客户端验收的
Klipper＋原生 Moonraker 软件候选**。现有 A／B／C 和 G0–G6 沿用，
不再增加阶段名称或独立计划。执行顺序固定为：已集成增量的合并后失败修正 →
一份锁定产物 → Fluidd 完整操作 → Mainsail 完整操作 → 按用户缺口补齐
Moonraker。当前系列无运动准备与有判别力的 G3 观测可穿插推进。

| 条件 | 实际限制与继续工作的范围 |
| --- | --- |
| PR 创建／审阅准入未满足 | 限制对应候选正常集成；先准备可审阅差异、验证和明确所需授权，不能用新外围批次掩盖集成阻塞 |
| 文件选择工具失效 | 限制实际页面出口；可准备同包与已支持的工具，API／模拟证据继续单独保留，不计算页面通过 |
| G3 unresolved | 禁止真实运动、实机打印验收及默认切换；具备隔离证据的软件路径可推进，模拟打印不代表实机准入 |
| 系列配置或目标板缺失 | 限制真实装配、目标性能和系列验收；先列具体资料缺项，不虚构配置或打印预算 |

运动诊断每次必须写明待区分的假设、固定输入、环境、期限及结果将改变
哪一项决策。已有证据相同且没有新判别条件时不重跑；一次有限成功只计
该条件通过，不关闭间歇异常。独立环境的源码、编译与无 JIT 有限对照
已有证据，不能继续把它列为未执行的下一项，也不以重复成功关闭 G3。现已封存一次同次输入失配现场，目标板
预算／验收仍缺；下一项诊断须利用固定现场补充能区分运行时、原生编译器与环境原因的
观测。若条件没有变化，登记缺失观测或隔离证据，不自动扩展运行次数
或新增库替换。

专用数学库／Rust 的采用由精度或目标性能缺口触发，并须保留独立参考、
边界行为及必要对照；库的数量和全面改写 C 内核不属于交付目标。
工具链使用 Node.js 26，最终仍须全部 Python 退役和完整 Moonraker 闭合。

进展只按进入 develop 的用户路径、同包客户端出口、目标验收、已实际
移除的 Python 依赖和发布出口报告。诊断、准备材料、计划修订分别标为
准备证据。某项外部阻塞持续存在且没有有意义的独立工作时，明确请求
缺少的授权／资料并报告阻塞，不以重复检查维持“正在推进”。
