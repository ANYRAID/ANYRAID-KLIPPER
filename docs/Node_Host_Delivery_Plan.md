## 目标与范围

最终目标保持 active：以 Node.js 26／TypeScript、专用数学库及必要时
Rust 数学库全面替代所有 Python，集成完整原生 Moonraker，将旧宏及原设计
覆盖的场景转换为消费级受控操作。构建、安装、启动、打印、维护、升级、
恢复和日常测试均须无 Python。现有 C MCU 固件及 C 运动内核可以保留。

当前仅新增适配 **ANYRAID Cycnumbris 500 系列**，其他机型全部最后处理。
已有 Delta 等测试仍用于保护兼容行为，不代表新增机型适配。系列内配置、
板卡和外设差异必须由可追溯材料核验。数学库与 Rust 只解决已经测得的
精度或性能缺口，不能通过换库或放宽容差掩盖异常。

## 本轮审计决定

交付顺序需要调整，最终范围不缩减。按“当前系列完整产品 → 交付出口 →
用户路径 → 权威所有者与依赖 → 最小实现 → 验收 → 集成／切换”推进。
Python 台账用于最终退役核对，不作为逐文件翻译队列。

已有进程服务、身份／文件／历史、打印状态机、配置／备份、普通 RESTART、
FIRMWARE_RESTART 和独立编译验收设施，继续复用；不重建通用事务框架。
当前默认打印入口仍为 Python，跟踪 Python 文件仍有 177 个；实际客户端
完整同包流程、完整 Moonraker、目标板和系列验收尚未完成。

首次候选曾领先 develop 927 个提交，现已通过两次正常 PR 分批集成。
现计划仍反复混合历史 CI、当前实现及最终准入，容易将独立工作串成等待链。
本轮收敛执行计划与当前证据入口；已通过的实现不重做，旧失败不删除。
这些是已核验的推进问题，不作为全部耗时的根因或新的软件完成声明。

### 按集成产品收紧下一出口

最终目标不改成“先做一个较小的替代品”。近期可验收结果固定为同一
Klipper＋原生 Moonraker 包贯通登录、上传／替换、预览、打印控制、
断连／重启恢复和历史；这个 A 出口仍不代表全部 Moonraker 或实机交付。
当前执行有三个已核验缺口：覆盖实现仍未集成；固定客户端完整同包流程
未封存；系列配置与 G3 尚未闭合。应围绕这些出口组织实现，而不是继续
按注册点数量或 Python 文件逐一翻译。

1. **先结束当前覆盖批次。** 冻结已实现的生产源码，补直接受影响的
   代际／失败边界及独立编译打印负载，通过精确新头 CI／审阅后正常 PR
   进入 develop。已有存储基准和回归只有指纹或覆盖范围变化时才重跑。
   必要失败须修复；无关扩展不加入本批。
2. **随即封存同包客户端 A 出口。** 使用集成后产物完成两套固定客户端
   的完整路径，把真实缺口映射到具体入口、所有者和最小修复。可先复用
   已通过基线检查页面设施；不得把旧包页面通过归到新覆盖包。页面问题
   优先于开启下一功能批次；工具确实不可用时保留未验项，继续有独立性
   证据的 M2c，不反复启动相同失败的浏览器操作。
3. **由产品缺口驱动后续 Moonraker。** M2c、队列、当前平台维护及剩余
   完整契约保留在总队列；每次只展开一个能交付的用户路径。若 A 或
   当前系列无运动装配暴露跨阶段的必要缺口，先修该缺口并记录其依赖，
   不因标签顺序推迟必需行为。非必要组件仍须在 C 前全部完成。

系列资料与精度判别是同一计划的准入工作，不另开一条广泛机型实现队列。
从现有真实配置建立“配置节／旧宏场景 → 已有原生操作 → 缺失能力 →
验证入口”映射；宏的开始、结束、取消、换料、调平等实际场景不得靠删节
或忽略模板绕过。先取得无运动预检结果，再只实现当前系列需要的差额。
G3 固定异常输入与共享实现判别，在覆盖集成后和队列软件出口复核；
有关安全失败先修，独立文件工作可继续，真实运动仍禁止。

每个批次报告必须给出可运行操作或产物、源码／产物身份、当前出口的
未通过项及下一具体动作。若一轮只有审计、文档或诊断结论，明确记为
准备工作，不计功能交付；不能靠再次扩写计划产生进展。

### 第 3b 批已核对的契约与实现边界

本节为当前批次的准入契约；运行实现与本机证据见
[覆盖验收](../host/contracts/native-overwrite-acceptance.json)，完整软件出口仍未关闭。
已封存 `4b6a2317` 的 626 个旧 Node 源码／依赖描述文件并逐项核对 Git blob。
1,024 文件、每文件 53,248 字节的 ext 基准中，目录查询中位比为 0.9844，
1,362 次并发目录查询 P95 0.3135 ms；事件循环 P99 1.8432 ms／最大
3.7478 ms。覆盖操作含完整实际收据校验与耐久 IO，不给其另设未约定的
50 ms 操作期限；这些数字不代表打印负载、目标板或旧 Python 性能通过。
核对基线为
Moonraker `1cfb0c41e468645951a371621f06d32777b6107c` 的
[file_manager.py](https://github.com/Arksine/moonraker/blob/1cfb0c41e468645951a371621f06d32777b6107c/moonraker/components/file_manager/file_manager.py)，
GitHub 读回 blob 为 `6fe3ce383f0ff1a36cd82a4222e0d6760ae0b93d`。
`_handle_file_move_copy`（583–646）、`_finish_gcode_upload`（896–936）、
`_process_uploaded_file`（948–979）和 `_sched_changed_event`（1097–1125）
分别证明移动使用实际解析目标、上传可替换同名文件及对应返回／事件语义；
`_handle_operation_check`（544–565）保护打印／暂停中的文件。
源码契约不能证明实际客户端或原生实现通过。

| 路径 | 必须实现和验证的行为 |
| --- | --- |
| 标准 multipart 上传覆盖 | 同一可见路径切换至新内容、新身份；旧身份不被重写或重新绑定。沿用上游 `create_file` 回执及事件，无 `source_item`；上传仍不隐式打印，受控打印请求另行提交 |
| 文件移动覆盖 | 保留源的内容、身份及时间，删除源路径，退役旧目标身份；返回一次 `move_file`，`source_item` 为原路径。已有目录目标按源 basename 解析，再保护实际目标身份 |
| 显式上传 ID | 已存在 ID 仍返回冲突，不把同 ID 重传解释成改写不可变收据；标准上传使用新 ID，新显式 ID 必须在提交时仍未占用 |
| 授权与竞争 | 先鉴权入口，再授权解析后的源／目标和被替换身份；授权等待后的源、目标、目录及设备代际变化必须重新校验。活动源移动及活动目标上传／移动均拒绝；暂停、停止未确认和维护占有同样保留现有更严格保护 |
| 元数据与预览 | 耐久提交后撤销旧源／目标缓存及旧缩略图地址；新路径按新收据解析。已开启的封存读者仍读原字节，历史记录不因名称替换绑定至新内容 |
| 生命周期 | 使用既有进程文件所有者和当前设备代际，迟到上传／授权不能落入新代。保留现有离线新文件上传；离线覆盖／移动仍属 M2c，不能削弱活动目标检查以假装支持 |
| 资源与性能 | 复用现有文件库、维护门、打印保护和有界 staging；计入新 blob、收据、事务、临时副本与旧目标共存的峰值空间。数量达到上限时仍应允许不增加最终数量的替换，但不能跳过峰值字节配额 |

当前单文件移动只需替换一个收据；覆盖会同时改变两个身份。上传覆盖还
引入新 blob，不能用“先删除目标再发布”或“先发布临时可见文件再改名”
完成，否则断电可丢失旧目标或暴露中间文件。当前实现须在既有文件库内采用
有界、可校验的耐久决定：决定前可取消并保留旧路径；决定后完成／恢复
操作，遇不确定写入则禁止后续读写直至 reopen。恢复先验证全部相关身份、
内容引用、命名空间及配额，再触碰收据或垃圾；拒绝外部改变和重复身份。
不重建通用事务框架，不把上传外部 staging 冒充已发布的复制源。

受影响回归必须覆盖下列可否证场景，而不是只检查成功返回：

1. 标准上传覆盖、新显式 ID、重复 ID 拒绝、校验和失败及已有嵌套目录。
2. 移动至文件和已有目录内的同名文件、同路径无物理改写、源／目标内容相同、共享 blob 引用及目标身份退役。
3. 未登录、策略拒绝、原始与解析目标授权、授权期间目标／目录／源变化及关闭／重启代际变化。
4. 打印和暂停中的源移动、目标上传／移动拒绝；无关文件覆盖在持续打印中成功；停止未确认不得放行。
5. 决定前取消／写入失败，决定后取消／sync 失败，以及每个允许的部分提交状态连续两次 reopen；通知只对应完整耐久提交，不在启动时重复发出。
6. 被替换旧 ID、旧预览、在途封存下载、元数据再生成、历史身份及事件数与路径；存储 charged bytes 与实际文件合计一致，零残留 reservation。
7. 文件数上限、峰值字节配额、未知／篡改事务、缺失／多出的收据和内容损坏均应无破坏地拒绝。

性能验收仍绑定源码及独立编译产物：真实 workspace 文件系统旧新 Node
目录热查询对照、两代持续打印中的上传／移动覆盖、各代活动源／目标拒绝、
通知／恢复与原操作数量均保留。沿用既有目录查询、事件循环 P99 50 ms／
最大 100 ms、步进提前量及停止期限；不以降低负载或放宽时间断言通过。

| 受影响路径 | 必要证据 |

证据；避免把新操作塞入旧计数使缺失操作被抵消。新增验证集中于变更的
风险，不为每个小入口重复构建全部跨组件组合；规定 CI 仍完整执行。
桌面与模拟数据不推导目标打印提速；目标预算由实际配置和硬件核定。
