## 目标与范围

最终目标保持 active：使用 Node.js 26／TypeScript、专用数学库及必要时
Rust 数学库，全面替代所有 Python，集成完整原生 Moonraker，并将现有宏
及原设计覆盖的业务场景转换为消费级受控操作。无 Python 的构建、安装、
启动、打印、维护、升级、恢复和日常测试均须闭合。
现有 C MCU 固件及 C 运动内核可保留。

当前仅适配 **ANYRAID Cycnumbris 500 系列**。完整 Moonraker 是首要功能
主线，其他机型全部最后处理。系列内板卡、外设和配置差异须取得资料后
核验，不假定所有机器相同。Rust 只用于已证实的精度或性能缺口，
不通过换库掩盖数值异常；数学库选择服从明确误差预算及目标板结果。

本次调整执行方式：从最终交付物确定用户路径，再识别依赖模块。
以可审阅、可复现的 Klipper＋Moonraker 候选包和当前系列实机准入为近期
目标；模块数量、提交数量及模拟测试数量不作为整体完成率。

一个诊断循环固定输入、假设、对照和可否证的结果；结束必须给出修复、
排除该假设或准确的缺失观测。若故障影响当前用户路径，继续修复；
若一轮判别已结束、必需观测暂缺或正在等待远程检查，则记录未关闭问题，
按调用链、资源所有权和失败传播证明下一条 Moonraker 契约独立后继续开发。
不要求先穷尽所有运动诊断；不得仅因功能名不同就宣称独立。
独立开发不能关闭失败、合并门槛或运动准入。

当前可考察的独立路径是复制／覆盖：文件事务不得调用校准或归零，
仍须验证授权、活动作业保护、元数据／通知、耐久恢复及编译并发打印。
涉及运动、设备重建或受影响恢复链时返回故障批次。一次只修改一批；
测试时冻结源码，等待期间不得改动正在测量的共享依赖，不开启多个代理。

当前已展开的校准输入／接受命令判别继续复用，不从头重做。新的失败
证据将主判别收敛到跨 MCU 校准偏移与即时触发的真实时钟边界；各项区分
产品实现、测试夹具与外部环境，只有反例能证明所属边界。修复必须同时
保留原失败场景和成功对照。历史间歇问题在多次成功后仍未解释时，下一步
是补足首个失败的事件／时钟／位置观测，而不是重复整套成功测试。

实际客户端完整流程使用同一编译产物补齐；页面工具条件未变时不重试
阻塞调用。当前系列配置到位即可做无运动安装和目标预算准备，不等待
M5 全部结束。真实运动继续遵守 G3。

每批结束按软件、客户端、集成、实机分别报告状态，并列出新增可用操作、
真正退役的 Python 依赖与下一阻碍。没有新的交付证据时不增加完成率。
数学库与 Rust 的引入必须对应已测得的缺口，不能作为另一条迁移队列。

## 从产品路径到实现任务

按交付物 → 用户路径 → 权威所有者 → 最小实现增量 → 验收 → 切换展开。
打印控制、Moonraker 和设备 IO 共用同一产品入口，不再建设第二套文件库、
打印状态机或恢复日志。复用分层如下：

| 所有者 | 职责与实现边界 |
| --- | --- |
| 进程服务 | Moonraker 监听器、身份、数据库、文件及历史跨设备重建保留；端点、权限、事件和持久化按固定上游逐项验收 |
| 打印／维护操作 | 权威状态机、类型化版本请求、前置检查、互斥、幂等、取消和恢复；客户端命令不绕过操作门禁 |
| 设备代际与 MCU | 配置、真实停止、运动时序、温控及 IO；旧代际排空后才释放，失败保留可查询故障，不伪报 ready |
| 数值与构建运行 | 固定精度参考、必要热路径基准、无 Python 依赖和目标安装；仅证实缺口后选 Rust，不先改写已有 C 内核 |

| 路径 | 本批实现边界及完成判据 |
| --- | --- |
| M2a 目录内文件可打印 | 标准目录创建／列举 → 目录内上传 → 元数据／缩略图／下载 → 按可见路径打印 → 删除文件及空目录；可见路径绑定原不可变内容和作业 ID，重启恢复、两套客户端及并发打印可验 |
| M2b 文件组织与替换 | 复制／移动／重命名／同名覆盖；源目标权限、冲突、活动作业、内容身份、元数据与事件一致，失败不产生错文件打印 |
| M2c 离线与递归清理 | Klipper 未就绪时 Moonraker 允许的管理、非空目录删除、活动文件保护、授权排空、通知及进程恢复闭合 |
