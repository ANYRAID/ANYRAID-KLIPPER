## 目标与范围

交付使用 Node.js 26／TypeScript、专用数学库及必要时 Rust 数学库的
Klipper 主机与完整原生 Moonraker 产品。在无 Python 环境完成构建、安装、
启动、打印、维护、升级、恢复和日常测试；以受控产品操作替代任意宏。
运动精度、停止保护与打印性能须经目标板和实机验证。现有 C MCU 固件与
C 运动内核可保留；语言与库选择服从数值正确性、调用成本和目标设备结果。
Rust 采用须有精度／性能证据，不作为未经验证的数值异常解法。

当前唯一机型范围为 **ANYRAID Cycnumbris 500 系列**；核验系列内硬件差异，
不推测配置一致。完整 Moonraker 是前期最高优先级功能主线，全部其他机型
适配放到最后。全面 Python 退役、完整功能替代及精度要求继续保留。

完整交付须同时满足：原有功能有替代及验收映射；固定上游 Moonraker 全量
契约闭合；宏场景完成受控操作替代；已知数值／崩溃问题关闭；目标设备
达标；默认及维护／测试入口无 Python；规定的集成与发布流程完成。
拒绝旧宏配置本身不代表宏产品化完成；功能替代与协议差异须分别记录。

## 验证、推进与报告规则

同时仅推进一个主要实现缺口。任务须明确所属出口、用户路径、当前缺口、
依赖、改动、验证阈值及完成后的切换／退役动作；只读资料核查可交替进行，
这不是启用多个代理的授权。仅在交付批次通过、失败改变路径或出现新阻碍
时更新本计划；日常进度在工作报告中说明，详细日志进入契约证据，计划
不再追加联调流水账。未完成代码草稿不作为可交付增量，保持可验证基线。

每个实现批次按“明确失败的用户路径 → 贯通产品入口 → 必要回归与性能 →
同产物客户端验收”推进。把持久资源、设备连接、路由与清理当作一次交接
处理；产品失败先修复，工具或外部资料阻塞按明确依赖切换任务，不跨过
原验收门槛、不重复无判别目的的测试。运行验证期间冻结其
源码，等待原执行句柄真正结束后再修改；保留首个失败及修复后的验证，避免
混用不同版本的证据。不存在新增变更或判别目的时不重复已通过的测试。

验证分算法／模块、独立编译产品链路、目标设备三级。先跑受影响检查，
再跑一次相关同包流程；相同提交已覆盖且无新风险时不重复。服务生命周期
任务检查恢复耗时、资源回收和事件循环影响；高频路径检查吞吐与尾延迟。
每项替代均保留必要性能证据，桌面微基准不推导整机提速。

| 受影响路径 | 必需性能证据 |
| --- | --- |
| 高频 API／订阅／文件读取 | 吞吐、P95／P99、事件循环延迟及有界资源回收 |
| 运动／打印热路径 | 精度参考、步进发送提前量、队列饥饿、CPU／内存及目标旧／新路径实际打印耗时 |
| 配置／数据库等维护 | 实际文件系统上的延迟、容量和失败耐久语义；tmpfs 不作为目标存储证明 |
| 生命周期／恢复 | 原监听器与持久资源保留、就绪耗时、重复恢复后的连接／定时器／句柄回收，不重放打印 |

L4 必须记录新代际就绪耗时、重复重启后的连接／定时器／文件句柄回收、
状态查询 P95／P99、事件循环尾延迟及最小步进发送提前量，并覆盖鉴权、
订阅、上传与打印并发。既有测试阈值属于桌面回归门槛，不能直接作为
目标设备性能预算。纯文档审计不新跑打印基准；实现变更后再验证受影响
链路。历史证据及源码哈希保留原版本，新批次生成新证据，避免改写历史。

目标性能预算先依据设备和运动上限确定，再比较旧／新路径的 P95／P99、
步进发送提前量、队列饥饿、CPU／内存、长期稳定性与真实打印耗时。
数学回归使用固定参考、边界用例和明确误差预算。缺少目标板、旧路径对照
或预算时标记待验；成功样本不能覆盖未定因失败。
