## 目标与范围

最终目标：交付当前系列可安装、可打印、可维护、可升级及回滚的
Klipper＋完整原生 Moonraker 产品。Node.js 26／TypeScript 全面替代
Python，专用数学库及必要时 Rust 用于已证实的精度或性能缺口；现有
C MCU 固件及 C 运动内核可保留。构建、安装、启动、打印、维护、恢复
和日常测试全部无 Python，旧宏全部场景须转换为消费级受控操作。

当前只适配 **ANYRAID Cycnumbris 500 系列**；其他机型最后执行 G6。
已有 Delta 等回归只保护兼容行为，不构成新增机型适配。默认打印入口
仍为 Python，177 个跟踪 Python 文件均在 klippy；完整目标尚未完成。
不通过更换数学库、放宽容差或改变完成定义掩盖异常。

## 目标审视与执行调整

总目标保留，近期调度改为交付出口：**A 同包软件闭环 → B 当前系列
受控试验 → C 全面退役发布**。A、B 不等于完整替代；C 仍需全部
Moonraker 契约、旧功能／宏场景、目标性能与精度及 G1–G5 闭合。
试验必需能力、装配及 G3 通过后可进入 B，无须等待非试验必需的可选
Moonraker 集成；这些集成仍是 C 的必需条件。

总到分路径固定为：最终产品 → 阶段出口 → 用户操作 → 权威所有者 →
最小差额 → 必要验收 → 正常集成／切换。Python 台账用于最终退役核对，
不作为逐文件翻译队列；模块、提交、测试数量不表示整体完成率。
服务、身份／文件／历史、打印状态机、设备代际及恢复设施继续复用。

本轮可确认的收口阻碍是待集成增量、实际页面工具失效和 G3 未关闭。
计划此前仍要求“首次集成／修复旧 CI”，与最新证据不符；现改为当前
候选审阅、正常集成及客户端验收。不能将这些因素推断为全部耗时的根因，
也不能用重新命名阶段、重复成功测试或迁移外围模块绕开出口。

## 从产品路径到实现任务

按交付物 → 用户路径 → 权威所有者 → 最小实现增量 → 验收 → 切换展开。
打印控制、Moonraker 和设备 IO 共用同一产品入口，不再建设第二套文件库、
打印状态机或恢复日志。复用分层如下：

| 所有者 | 职责与实现边界 |
| --- | --- |
| 进程服务 | Moonraker 监听器、身份、数据库、文件及历史跨设备重建保留；端点、权限、事件和持久化按固定上游逐项验收 |
| 打印／维护操作 | 权威状态机、类型化版本请求、前置检查、互斥、幂等、取消和恢复；客户端命令不绕过操作门禁 |
| 设备代际与 MCU | 配置、真实停止、运动时序、温控及 IO；旧代际排空后才释放，失败保留可查询故障，不伪报 ready |
| 数值与构建运行 | 固定精度参考、必要热路径基准、无 Python 依赖和目标安装；仅证实缺口后选 Rust，不先改写已有 C 内核 |

### 从最终交付物收敛当前批次

最终交付物是当前系列可安装、可升级、可回滚的无 Python 产品。
由该交付物向下确定用户路径、权威所有者和必需替代依赖；不以逐个
Python 文件翻译作为工作队列。每批的交付物是标准产品入口中的一条
完整操作及其证据，完整 Moonraker 的其余契约继续登记为待完成。

M2b 包含文件、目录、复制和覆盖，按下表顺序验收。各批沿用同一
存储、身份、打印状态机及产品服务，复用恢复设施；不能只提交纯规划器
或微基准就宣称交付路径。单文件及目录移动均已提交软件增量，后续直接
复用其已验证边界；页面、目标板和集成缺项仍按各自门槛关闭。

| 当前顺序 | 用户可见交付物 | 最小实现与退出条件 |
| --- | --- | --- |
| M2b 第 1 批 | 单文件重命名／移动到已有目录后仍可预览、下载和选择打印 | 固定 `server.files.move`／HTTP 参数与返回；源目标授权、活动文件保护、持久路径变更、不可变内容／作业身份、旧新元数据及通知一致；同盘恢复／失败回归、编译混合负载和实际客户端验收分别记录 |
